## [Unreleased]

- Неизвестный исход записи настроек больше не удаляет обычный черновик. Новый recovery GET сохраняет правки при несовпадении, обновляет baseline для явного нового сохранения и отдельно показывает совпадение состояния без подтверждения исходной квитанции. Save блокируется до успешного чтения; отправленные secrets/MCP/provider connection drafts очищаются. Typed saved=true post-commit failure не предлагает повторную запись. Проверочный GET принадлежит окну и отменяется при закрытии; поздний callback не меняет повторно открытый диалог.

- Создание задания входа в аккаунт сохраняет полученный канонический job ID до проверки остальной квитанции. Missing/invalid/foreign snapshot не забывает уже принятое задание и не открывает повторный create: доступны отдельные GET/явный DELETE, при этом непроверенные disclosure/attach command не показываются. Readback отделён от исходной квитанции, ID переживает закрытие/повторное открытие окна. Добавлен тест с настоящим gateway/HTTPX proxy и повреждением ответа после реального создания задания; daemon/CLI simulated, вход к провайдеру не выполняется.

- Непрерывный SpeechRecognition теперь сохраняет один GStreamer capture pipeline во время VAD/декодирования предыдущих 15-секундных блоков. GstBuffer, пересекающий границу блока, разбирается полностью; PCM не обрезается. Результаты обрабатываются по порядку, stop/EOF дожидаются очереди, abort/Panic/close останавливают её. Очередь ограничена двумя ожидающими блоками и одним обрабатываемым; перегрузка явно останавливает запись и сообщает владельцу. Тест сравнивает все PCM samples 45-секундной записи и проверяет перегрузку при удержанном реальном декодировании. Границы слов и качество на физическом микрофоне ещё требуют проверки.

- Диктовка принимает штатный client provider результат `{no_speech: true}` наравне с серверным no_speech status. Неизменённый browser_speech больше не получает сообщение о некорректной пустой расшифровке при отсутствии речи; черновик сохраняется, показан обычный статус отсутствия речи.

- Добавлен мост SpeechRecognition/webkitSpeechRecognition для проверенных модулей: нативный consent с указанием навыка/шлюза/English (US), GStreamer capture, локальный VAD/PocketSphinx и final result/error/end events. Неизменённый browser_speech проходит от собственного reviewed JavaScript до GTK-черновика. Поддержаны start/stop/abort, последовательные final indices, отклонение неподдерживаемого языка и явный отказ для MediaStreamTrack input. Нативная остановка освобождает все recognition reservations данного владельца до JS acknowledgement. Заявление навыка о destination сохранено отдельно от native capability; полная Web Speech parity и бесшовный continuous capture ещё не подтверждены.

- Перед локальным распознаванием добавлен отдельный нативный WebRTC VAD из PocketSphinx: ограниченный PCM через stdin, без сети/файлов и загрузки модели. Записи без 180 мс подряд обнаруженной речевой активности возвращают no_speech до запуска декодера. Общая отмена/close/deadline охватывают обе стадии; ошибочный VAD не разрешает запуск модели. Проверенные DC/низкий и умеренный синтетический шум отсекаются, исходная человеческая запись сохраняет правильный результат. Очень короткие реплики и качество на реальном шуме остаются ограничениями.

- PocketSphinx подключён к нативной диктовке: отдельный выбор English (US) в GTK-списке движков, явное место обработки и лимит 15 секунд, локальное состояние окна без записи выдуманного provider key на шлюз. Настоящий GStreamer WAV проходит через модель до черновика; изменения черновика/комнаты дают отдельное предложение вставки. Сохраняются capture lease, отмена, выход из комнаты, Panic и закрытие. Browser SpeechRecognition и VAD остаются открытыми.

- Добавлена основа локального распознавания: PocketSphinx 5.1.1 и английская модель в Flatpak, ограниченный WAV PCM16 mono 16kHz через stdin без временных аудиофайлов, отмена с завершением дочернего процесса, изоляция экземпляров и явные ошибки языка/модели. Исправлен upstream stdin probe для не допускающего seek канала. Настоящая запись goforward распознаётся реальным движком; подключение диктовки/SpeechRecognition, другие языки и VAD ещё не реализованы.

- Редактор проекта проверяет полный ответ update по исходному ID/комнате и отправленным name/pinned/closed. Чужая, плоская, неполная или противоречащая запросу запись не закрывает форму. Неизвестный исход блокирует повтор записи до отдельного GET; черновик сохранён, свежая запись становится основой сравнения флагов, совпадение состояния не выдаётся за квитанцию исходного POST. Поля блокируются на время записи; закрытие отменяет readback и не возрождает UI/cache после позднего ответа принятой записи. Новый project-update тест выполняет настоящий handler и registry mutation с контролируемыми wire faults. Build и восемь выбранных проверок прошли; project-update и core CRUD подтверждены в GNOME 51 Flatpak.

- Добавлено нативное окно сведений проекта с addressed GET, происхождением рабочей папки, опубликованной активностью, отдельным решением закрытия, lifecycle и ревизиями. Полная последняя квитанция создания/изменения хранится отдельно от свежей компактной записи: clone URL/trusted_at не выдумываются из GET и не выдаются за текущий Git checkout. Ошибки чтения сохраняют прежние сведения с пометкой, успешное отсутствие очищает их, закрытие отменяет pending GET. Новый project-details тест использует настоящий registry/summary handler; core CRUD дополнен проверкой фактической квитанции attach. Build и семь выбранных проверок прошли; project-details и core CRUD подтверждены в GNOME 51 Flatpak.

- Резервные Pause/Hurry окна задачи теперь следуют pinned resolve_task_lineage: canonical empty fields перекрывают metadata, null использует metadata; корневой retry требует согласованных original_task_id/timeout_retry_from и роли root. Дочерние и нечитаемые записи не получают эти операции; сохранённый неизвестный запрос не обходит обновлённую принадлежность задачи. Stop/Wrap up сохраняют прежнюю область, основная WorkState projection остаётся источником действий. Новый test:task-lineage:gjs сравнивает 16 случаев с настоящим primary predicate и проверяет GTK controls, stale callbacks и retained request replay. Build и десять выбранных проверок прошли; task-lineage и task-controls подтверждены в GNOME 51 Flatpak.

- Статус подтверждения сообщения привязан к редакции черновика, которую он очистил: поздняя квитанция прежней отправки больше не заменяет предупреждение нового черновика. Выбор и удаление цитаты увеличивают редакцию черновика; изменение reply target во время ожидания сохранения параметров комнаты требует нового явного Send. Расширенный room-cognition-chat воспроизводит запоздалую настоящую квитанцию через WebSocket и проверяет оба изменения адресата ответа без автоматической отправки. Сценарий прошёл на хосте и GNOME 51 Flatpak. Полный запуск 199 команд дал 198 успешных результатов и один отказ Xvfb; отдельный повтор routing-journal успешен при неизменных входных файлах.

- Markdown-компоненты карточек, виджетов и настроек отображают форматированный текст средствами GTK, включая ссылки, код, таблицы и раскрывающиеся блоки. Добавлены копирование исходника и кода, просмотр исходника и навигация больших таблиц. HTML разбирается как данные; активное содержимое не исполняется, изображения не загружаются. Исправлен вызов буфера обмена GJS, в том числе для диктовки и расшифровки вызова.

- Email и URL в карточках, виджетах и настройках проверяются перед отправкой. Адресные поля нормализуют переводы строк и краевые ASCII-пробелы, сохраняя обычный текст и пароль. URL используют встроенный WHATWG-парсер; табличные ссылки также корректно кодируют допустимые пробелы в пути.

- Числовые поля карточек, виджетов и настроек проверяют `step` с базой от `min` или исходного значения, десятичный синтаксис и диапазон. Десятичная арифметика устраняет ошибки двоичного округления, а типы полей нормализуются по закрытому набору шлюза. Добавлена команда `npm run test:forms`.

- Диалог сохранения медиа навыка получает родительское окно GTK вместо контейнера. Медиа в скрытой вкладке виджета приостанавливается.

- Квитанция `api_command` и записи с `task_id_pending` не превращаются в ссылки на задачи и не запускают загрузку вымышленных эпизодов. Запрос исправления навыка сохраняет понятный текст в истории через `visible_text`.

- Повторное исправление навыка получает отдельный идентификатор отправки, чтобы шлюз не подавлял новую команду как дубль предыдущей. Приём команды и неизвестный результат отправки показываются отдельно от завершения исправления.
